# Виноградов — фабрика авторских голосов (Voice DNA)

Мастер, который превращает реальные образцы текста в персональный voice-скил.
Голос **измеряется** из корпуса (детерминированный анализатор частот по 4 слоям
авторского стиля В.В. Виноградова), а не угадывается моделью.

> Форк и развитие [`voice-dna-builder`](https://github.com/ponomr/voice-dna-builder)
> Алексея Пономаря. Что добавлено: 4-слойный отчёт об авторском стиле, подпись по
> **отклонению** служебных слов от нормы языка (мини-Burrows), burstiness (ритм),
> лексическое богатство (TTR / Yule's K / hapax), авто-разделение **стилистических**
> оборотов и **тематического** шума. Методика voice-profile — в духе
> `brand-voice-writer` из [Tiger Data marketing-skills](https://github.com/timescale/marketing-skills).

## Когда использовать

- «Склонируй мой голос», «настрой стиль под меня/канал/бренд».
- «Собери voice dna», «сделай скил, который пишет как автор X».
- «Обнови голос новыми текстами» — инкрементальная дозаливка (см. ниже).

## Что внутри

| Ресурс | Назначение |
|---|---|
| `scripts/analyze_corpus.py` | Детерминированный анализатор: 4 слоя авторского стиля — лексика (служебные слова как подпись, обороты, богатство), синтаксис (длина, **burstiness**), композиция (абзацы, зачины, концовки), образ автора (тон, регистр) |
| `scripts/extract_telegram.py` | Корпус автора из JSON-экспорта Telegram Desktop (фильтрует форварды, медиа, ссылки) |
| `references/extraction-guide.md` | Вопросы интервью + маппинг «отчёт → шаблон» + схема voice-profile.json |
| `references/voice-skill-template.md` | Шаблон выходного SKILL.md (кто / эталоны / off-brand / табу / измеренный отпечаток) |
| `references/universal-anti-slop.md` | Общий анти-AI-слой, встраивается в каждый собранный скил |

## Принципы (почему так)

Подтверждены практикой и исследованием LLM voice-cloning — примеры бьют правила
в 2–3 раза, а «усреднение» к жанровому центроиду — главный враг клона:

- **Примеры > правила.** Голос не описывается инструкциями. 3–4 дословных эталона
  дают модели больше, чем страница правил про стиль.
- **Негатив сильнее позитива.** «Так автор НЕ сказал бы» (off-brand, табу) калибрует
  сильнее, чем «делай так».
- **Никаких противоречивых хеджей** («используй тире, но не часто», «будь ироничным,
  но не циничным») — модель от них дуреет. Либо чёткое да/нет с примером, либо эталон.
- **Три контекста не смешивать:** *голос* (этот скил) ≠ *правила работы* (как
  переписывать/фактчекать) ≠ *издание/аудитория/домен*. В голос — только голос.
- **Только настоящее.** В отпечаток идут реальные частоты из отчёта. Контентные
  слова — это ТЕМЫ, не голос. Анализатор сам отделяет стилистические обороты от
  тематического шума (имена/термины) и фильтрует по document-frequency.
- **Подпись — через отклонение, не сырую частоту.** «и/в/не» частотны у всех;
  различает над/недо-употребление относительно нормы языка.
- **Анти-слой общий, голос личный.** Баны AI одинаковы для всех (см. anti-slop);
  всё остальное индивидуально.
- **Язык вывода = язык образцов** (списки слов в анализаторе заточены под русский;
  для не-русского корпуса числа анализатора ориентировочные — опираться на дословные эталоны).

## Рабочий процесс

Интерфейс мастера — на русском; собранный скил — на языке образцов.

> **Голос уже есть?** Если у пользователя есть скил с `references/voice-profile.json` —
> не интервьюировать заново, перейти к «Обновлению голоса».

### Шаг 1 — Интервью (порциями)
**Блок А:** имя/ник автора (отсюда slug); кто/роль; темы; каналы (где, длина, цель).
**Блок Б:** стиль одной фразой; нужны ли тональности; личные анти-правила (чего
НИКОГДА — эмодзи, хэштеги, мат, капс); любимые словечки (опц. — корпус покажет).

### Шаг 2 — Сбор корпуса
5–20+ реальных образцов: вставка в чат (через `---`); файл (.txt/.md); JSON-экспорт
Telegram (`extract_telegram.py`). Дать и короткие реплики, и длинные — поймать ритм.
<5 образцов → честно предупредить: голос выйдет приблизительным.

### Шаг 3 — Анализ
```bash
python3 ~/.claude/skills/vinogradov/scripts/analyze_corpus.py /tmp/corpus.txt
python3 ~/.claude/skills/vinogradov/scripts/analyze_corpus.py --selftest   # регрессия токенизатора после правок
```
Отчёт даёт реальные числа по 4 слоям. **Не выдумывать статистику** — брать из отчёта.

Анализатор до подсчёта вырезает ссылки, e-mail и @упоминания и не рвёт предложения на
точках сокращений и инициалов («т. е.», «3 тыс. руб.», «М. Ю. Иванов»). Число вырезанного —
в шапке отчёта. Без этого ритм и словарь считаются по мусору: ссылки и обрывки от точек
в сокращениях искусственно раздувают долю «длинных»/«коротких» предложений. Голос,
собранный по корпусу со ссылками до этой правки анализатора, стоит пересчитать при
следующем обновлении и сверить показатели ритма.

### Шаг 4 — Сборка скила (по `references/voice-skill-template.md`)
Заполнить секции шаблона. Маппинг слоёв отчёта → секции:

| Секция | Откуда (слой отчёта) |
|---|---|
| Кто это | интервью + средняя длина (Слой 2). Справка ДЛЯ МОДЕЛИ, в текст не выносить |
| Эталоны (3–5) | **дословные** образцы из корпуса — половина качества |
| Off-brand / Табу (столько же, сколько эталонов) | контраст с anti-slop + «чего в корпусе нет» + анти-правила интервью |
| Словарный отпечаток | Слой 1: служебная подпись (отклонение) + вводные + стилистические обороты дословно |
| Ритм и композиция | Слой 2 (burstiness/CV) + Слой 3 (зачины-сигналы, % концовок-вопросов) |

**Пример с адресом.** Если источник образца известен (ссылка на пост, дата, файл) — хранить
его в `voice-profile.json` → `corpus_sources` (номер образца → адрес). В сам скил ссылки не
идут (токены). Зачем: любой on-brand-фрагмент можно открыть и убедиться, что это автор,
а не пересказ. Так устроены стилевые паспорта в
[gasyoun/RuWritingStyles](https://github.com/gasyoun/RuWritingStyles): каждое правило
подкреплено ссылкой на реальный пост.

Вместо `{{ANTI_SLOP}}` вставить секцию из `references/universal-anti-slop.md`.
Если автор сам сыплет тире (отчёт это укажет) — смягчить пункт про тире.
Парцелляцию автора в скил НЕ переносить и в эталоны не брать (у нейросетей это тик —
клон начнёт сыпать обрубками сильнее автора); короткий ритм кодировать короткими
ПОЛНЫМИ предложениями.

### Шаг 5 — Установка
Записать `~/.claude/skills/voice-{{slug}}/SKILL.md` (slug — латиница kebab-case).
Рядом — `references/voice-profile.json` (схема в extraction-guide) для дозаливки.

### Шаг 6 — Проверка
Сообщить команду `/voice-{{slug}}`, предложить пробную генерацию: тема из корпуса,
2–3 якоря из ОДНОГО реального образца. Критерий: показать автору пробу рядом с ДРУГИМ
его реальным текстом на близкую тему (не тем, откуда якоря, — иначе проверка нечестная);
провалы по лексике, ритму или концовкам называть конкретно. Не похоже —
вернуться к Шагу 4, поправить эталоны/отпечаток (калибровка примерами > правил).

## Обновление голоса (без повторного интервью)

1. Прочитать `voice-profile.json`; интервью не повторять (только уточнить изменения).
2. Новые образцы добавить к корпусу; прогнать анализатор по объединённому корпусу.
3. Показать diff подписи (что добавилось/выпало); пересобрать SKILL.md; обновить профиль.

## Схема voice-profile.json

```json
{
  "version": 1, "created": "2026-06-23", "updated": "2026-06-23", "language": "ru",
  "interview": {"name": "", "slug": "voice-ivanov", "who": "", "topics": [],
    "channels": [{"name": "", "length": "", "purpose": ""}],
    "style_phrase": "", "tonalities": [], "anti_rules": []},
  "corpus": ["образец 1 дословно", "образец 2 дословно"],
  "corpus_meta": {"samples": 12, "source": "telegram-export + вставка"},
  "corpus_sources": {"0": "t.me/channel/1234", "1": "posts-archive.md, 2026-05-14"},
  "measured": {"avg_len": 0, "cv": 0.0, "fillers": {}, "fw_over": [], "ngrams": [], "tire_heavy": false}
}
```
