# Гайд по извлечению Voice DNA

Как превратить интервью + сырые образцы в заполненный `skill-template.md`.

---

## Часть 1. Интервью (что спрашивать)

Спрашивать порциями, не вываливать всё сразу. Сначала блок А, потом Б.

### Блок А — личность и охват (обязательно)
1. **Имя/ник** автора скилла (как подписывать стиль). Отсюда же `skill-slug`.
2. **Кто ты**: род занятий, роль, бэкграунд (1–2 фразы).
3. **Темы**, на которые пишешь чаще всего.
4. **Каналы**: где публикуешь? (чат / личный канал / LinkedIn / X / e-mail / блог).
   Для каждого — примерная длина и цель.

### Блок Б — тон (обязательно)
5. **Стиль одной фразой**: прямой? тёплый? саркастичный? академичный?
6. **Тональности**: нужны ли переключатели (нейтрально / мягче / жёстче / ироничнее)?
   Какие именно? Дефолт — «нейтрально».
7. **Личные анти-правила**: чего ты НИКОГДА не делаешь? (эмодзи, хэштеги, мат, капс…).
8. **Любимые словечки/обороты**, если знаешь за собой (необязательно — корпус покажет).

### Блок В — образцы (критично для качества)
9. Попросить **5–20+ реальных образцов** в этом голосе. Чем больше, тем точнее.
   Форматы приёма:
   - вставить прямо в чат (образцы разделять строкой `---`);
   - дать путь к файлу (.txt / .md / экспорт переписки);
   - JSON-экспорт Telegram Desktop → прогнать `scripts/extract_telegram.py`
     (без `--from` покажет список авторов; с `--from "Имя"` соберёт корпус,
     отфильтровав форварды, медиа и чисто ссылочные сообщения);
   - указать несколько коротких + пару длинных, чтобы поймать ритм.
   Если образцов мало (<5) — честно предупредить: голос выйдет приблизительным,
   скилл будет опираться в основном на интервью.

---

## Часть 2. Анализ образцов

Сохранить образцы во временный файл и прогнать:

```bash
python3 ~/.claude/skills/voice-dna-builder/scripts/analyze_corpus.py /tmp/corpus.txt
```

Отчёт даёт детерминированные числа. Не выдумывать статистику — брать из отчёта.

## Часть 3. Маппинг отчёт → шаблон

| Поле шаблона | Откуда брать |
|---|---|
| `Средняя длина` | «Длина и ритм» → средняя длина образца |
| Каналовые диапазоны длины | медиана + распределение коротких/длинных |
| «Вводные / слова-подписи» | секция «Вводные» (только реально частые, не из общего списка) |
| «Характерные обороты» | секция «Характерные обороты (n-граммы)» — дословные многословные обороты автора |
| Структура (как открывается мысль) | секция «Начала и концовки» → первые слова предложений |
| Финал текста (точка/смайл/обрыв) | секция «Начала и концовки» → распределение концовок |
| «Маркеры тона / иронии» | секция «Маркеры», топ эмодзи |
| Пунктуационные привычки | секция «Пунктуация» (тире, скобки, многоточие) |
| Тональность «ироничнее» | реальный маркер автора (его эмодзи/смайл), а не выдуманный |
| Примеры в Usage / Каналы | брать ДОСЛОВНЫЕ образцы из корпуса как эталон |

### Важные правила маппинга
- **Только настоящее.** Если слова нет в отчёте — не пихать его в «подпись голоса».
  Скрипт проверяет реальный список кандидатов; бери лишь то, что реально частотно.
- **Тире-исключение.** Если `Тире` в отчёте > числа образцов (автор сам сыпет тире) —
  смягчить анти-слой: не баним тире жёстко, только защищаем от AI-накопления подряд.
- **Игра длиной.** Если высоки и доли коротких, и доли длинных предложений — явно
  прописать «чередуй рубленые и длинные» в правилах.
- **Мало эмодзи/маркеров** → не выдумывать тональность «ироничнее»; предложить
  автору пропустить её или задать маркер вручную.
- **N-граммы — дословно.** Обороты из секции «Характерные обороты» вставлять в скилл
  как есть («по сути да», а не «по сути»); это многословная подпись голоса.
- **Концовки.** Если автор обычно не ставит точку / заканчивает смайлом — явно
  прописать это в правилах канала (AI по умолчанию «причёсывает» финал точкой).
- **Примеры — это половина качества.** Реальные образцы в секции Usage калибруют
  модель сильнее любых правил. Всегда вставлять 3–4 настоящих.

## Часть 4. Сборка и сохранение

1. Взять `skill-template.md`, заменить все `{{...}}`.
2. Вместо `{{ANTI_SLOP}}` вставить RU- или EN-секцию из `universal-anti-slop.md`
   (по языку корпуса; при смешанном — обе).
3. Удалить пустые блоки (каналы/тональности, которых нет).
4. `slug` = транслит/латиница имени, kebab-case, напр. `style-writer-ivanov`.
5. Создать `~/.claude/skills/{{slug}}/SKILL.md` и записать результат.
6. Проверить frontmatter: валидный `name` + `description` с триггерами.
7. Сохранить профиль голоса в `~/.claude/skills/{{slug}}/references/voice-profile.json`
   (схема ниже) — он позволяет обновлять голос без повторного интервью.
8. Сообщить пользователю: как вызвать (`/{{slug}}`), и предложить пробную генерацию
   для калибровки.

### Схема voice-profile.json

Хранит всё, что нужно для пересборки. Корпус — дословно, образцы как строки массива.

```json
{
  "version": 1,
  "created": "2026-06-12",
  "updated": "2026-06-12",
  "language": "ru",
  "interview": {
    "name": "Имя автора",
    "slug": "style-writer-ivanov",
    "who": "род занятий, роль — из блока А",
    "topics": ["тема 1", "тема 2"],
    "channels": [
      {"name": "Telegram-чат", "length": "до 300 символов", "purpose": "реплики коллегам"}
    ],
    "style_phrase": "прямой, с иронией",
    "tonalities": ["нейтрально", "ироничнее"],
    "anti_rules": ["без хэштегов", "максимум 1 эмодзи"]
  },
  "corpus": ["образец 1 дословно", "образец 2 дословно"],
  "corpus_meta": {"samples": 12, "source": "telegram-export + вставка в чат"}
}
```

## Часть 5. Обновление существующего голоса

Триггер: «обнови мой голос», «добавь новые образцы», повторный запуск с тем же именем.

1. Прочитать `voice-profile.json` из скилла пользователя. Интервью **не повторять** —
   только спросить, изменилось ли что-то (каналы, тон, анти-правила).
2. Новые образцы добавить к `corpus` из профиля; прогнать `analyze_corpus.py`
   по объединённому корпусу.
3. Показать diff подписи голоса: новые вводные/обороты ↔ выпавшие.
4. Пересобрать SKILL.md по Частям 3–4; обновить в профиле `corpus`, `corpus_meta`
   и `updated`.
5. Если `voice-profile.json` отсутствует (скилл собран старой версией) — честно сказать,
   что для обновления нужны интервью и образцы заново, и предложить полный прогон;
   в конце сохранить профиль, чтобы дальше обновлять инкрементально.
